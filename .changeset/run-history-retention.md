Workflow Graph can delete old run history when a host asks. `runs: { retentionMs }` on `createWfGraphApp`, `createWfGraphRunner` and the `wfWorker` config sets how long an ended run is kept after it completed. Once an hour, in the same upkeep that sweeps the event inbox, the worker loop deletes ended Executions older than the window with their node logs, wait rows and timelines, then workflow audit rows that name no run, such as Refused Starts, then draft snapshots that no Execution references and no Draft run has pinned within the window. A Worker runs the sweep on its Cron Trigger tick. A run in flight is never deleted, and published versions always stay. A run that an Event's delivery opened, and a Refused Start recorded for a delivery, are kept while that delivery's inbox row exists, because a redelivered inbox row is answered from them and deleting either early would open a second run. The option is off by default, so a host that leaves it out keeps every run. Every sweep, the event inbox's included, deletes at most 500 rows per batch, down from 1,000 for the inbox, so one batch holds SQLite's single writer for about half as long. Startup refuses a `runs.retentionMs` that is not an integer from one hour to 100 years, and an `events.retentionMs` that is not a positive integer of at most 100 years. Migrations on both backends add a `last_pinned_at` column to `workflow_versions`, which records when a Draft run last pinned a snapshot, and partial indexes on `workflow_executions.completed_at` and on draft snapshots' `last_pinned_at`. On SQLite they also add indexes on `workflow_executions.workflow_version_id` and `workflows.published_version_id`, which serve the sweep and the deletes it cascades into.

The editor states the window so a builder knows why old runs are gone: a workflow's Runs list and the All Runs list read "Runs are deleted 30 days after they finish." for a 30-day window, and say nothing when the host keeps every run. `getExecutions` and `getExecutionsGlobal` carry the window as `runRetentionMs`, null when unset, so the client and core must be on the same version.
